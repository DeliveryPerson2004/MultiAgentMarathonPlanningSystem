# 毕业论文题目

《基于A2A协议的马拉松赛事多智能体策划系统》

# 论文思路

本论文面向马拉松赛事筹备过程中的跨部门沟通需求，研究基于大语言模型与A2A（Agent2Agent）协议的多智能体协作方式。赛事主办方设立自己的智能体，交通等相关部门也分别拥有独立的智能体。赛事主办方相关负责人通过对话或任务界面调用主办方智能体，由其根据负责人的要求，与其他部门的智能体开展需求传递、信息咨询、方案沟通和反馈汇总，辅助推进赛事策划工作。

系统以真实组织之间的协作关系为建模依据。各智能体服务于所属组织，依据本部门的资料、职责和业务流程处理收到的请求；主办方智能体负责发起和跟进沟通，其他部门智能体独立作出回复、提出补充要求或返回修改建议。论文重点关注这种跨组织、跨服务的智能体通信如何支撑赛事策划，以及沟通过程如何保留部门意见、跟踪未解决事项并支持负责人决策。

## 1. 研究问题与总体方案

论文重点研究三个问题：一是如何将主办方负责人的自然语言要求转化为面向相关部门的沟通请求，并通过A2A协议找到和调用对应智能体；二是如何在各部门独立处理请求的前提下，完成多轮沟通、补充材料和方案调整；三是如何汇总不同部门的意见，识别相互冲突的条件，并将进展、分歧和待决策事项清晰反馈给主办方负责人。

系统拟首先实现主办方智能体与交通部门智能体之间的协作，再按原型需要扩展医疗保障、场地管理等部门智能体。主办方负责人是主办方智能体的直接使用者，可要求其就候选赛道、赛事时间和参赛规模向交通部门咨询，也可查看回复、补充资料或要求继续沟通。交通部门智能体依据自身可用资料处理请求，返回可行性意见、条件限制或待补充信息。需要部门人员判断或确认的事项，由该部门按自身流程处理后再反馈。

例如，负责人提出“请与交通部门沟通周日上午使用候选路线举办赛事的可行性”，主办方智能体整理路线、时间和规模等信息，通过A2A向交通部门智能体发起请求。若对方反馈某路段在拟定时段存在冲突，主办方智能体向负责人展示该意见和备选调整方案；负责人选择调整时间或路线后，再由主办方智能体继续沟通，并记录每轮方案及对应回复。

## 2. A2A协议下的协作机制

依据[A2A官方规范](https://a2a-protocol.org/latest/specification/)，各组织的智能体作为独立服务提供接口，通过Agent Card描述可提供的能力、服务地址和访问要求。主办方智能体根据沟通目的选择相应部门智能体，使用协议消息传递请求与回复，使用Task跟踪需要持续处理的事项，并通过Artifact交付部门反馈文件或方案材料。实现阶段固定所采用的协议及SDK版本。

A2A提供智能体之间的通信与互操作能力，沟通对象选择、业务意见处理和人工确认由各方应用实现。各部门保有自身的数据和内部处理逻辑，只交换完成当前沟通所需的信息。主办方智能体可以同时咨询多个部门，也可在收到某部门意见后，再向其他相关部门沟通其影响。系统记录沟通对象、任务标识、关联赛事、方案版本、回复来源及处理状态，支持异步等待、信息补充和失败后的有限重试。

## 3. 部门意见协调与负责人交互

主办方智能体维护赛事的当前方案和沟通记录，按部门呈现已收到的意见、待补充材料、处理中事项和待负责人决策的问题。对不同部门返回的时间、路线和资源条件进行比对，发现冲突时保留各方原始意见及其依据，整理可供讨论的调整建议，再根据负责人的指令或已授权范围继续沟通。对于尚未回复或仍有分歧的事项，明确标注其状态；方案汇总应关联具体版本，避免将旧版本回复误用到新方案。

各部门智能体可接入本部门提供的业务资料，并按需要借鉴[检索增强生成方法](https://arxiv.org/abs/2005.11401)辅助形成有依据的回复。领域知识检索作为部门智能体的支撑能力，论文研究重点放在跨部门沟通和协作流程。系统区分咨询建议、待人工确认意见和已确认反馈，使负责人能够了解每条回复的来源与业务状态；正式部门确认应由对应部门的实际流程产生并记录。

## 4. 原型实现与实验验证

原型拟提供主办方负责人使用的交互界面，实现赛事需求录入、调用主办方智能体、查询部门能力、发起A2A沟通、查看部门回复、补充信息、确认调整方案和导出沟通汇总等功能。同时搭建独立的交通等部门智能体服务，并提供简化的部门人工处理入口，以演示部门回复和确认流程。若没有真实部门接口和业务数据，使用明确标注的模拟部门服务与测试资料验证流程。

实验拟构造初次咨询、材料不完整、多轮方案调整、跨部门条件冲突、部门延迟回复以及负责人修改需求等案例。在相同测试资料和可比模型配置下，对比仅支持一次请求与回复的协作流程，以及支持状态跟踪、多轮沟通和人工确认的完整流程。主要指标包括请求送达与正确关联率、沟通任务完成率、材料补充成功率、已知冲突识别率、方案与回复版本对应准确率、人工介入次数、响应耗时及模型调用成本。对意见汇总的完整性和负责人使用体验采用预先定义的标准进行人工评估。

另通过新增部门智能体、替换部门服务实现，以及服务超时后的恢复实验，检查A2A接口互操作、接入修改量和沟通状态保持情况。实验分别分析协议接入能力与业务协作机制的效果，并根据实际结果评价系统能否辅助主办方负责人跟进跨部门沟通。

## 5. 预期成果与研究特色

预期形成一个可由赛事主办方负责人调用的主办方智能体、若干可独立运行的部门智能体服务、一套跨部门沟通与状态跟踪机制，以及相应的测试案例和实验分析。论文拟重点体现组织职责与智能体的对应关系、基于A2A的跨部门多轮通信，以及负责人参与的意见协调和方案调整流程。研究特色定位于马拉松赛事筹备场景中的跨组织智能体协作设计与验证，具体效果以实验结果为依据。

2. **Hong S, Zhuge M, Chen J, et al. MetaGPT: Meta Programming for A Multi-Agent Collaborative Framework. 2023. arXiv:2308.00352.** [论文链接](https://arxiv.org/abs/2308.00352)

   主要内容：将标准作业流程引入多智能体协作，通过角色分工和中间结果验证组织复杂任务。对本课题的参考价值：借鉴流程化协作思想，明确部门沟通所需材料、回复内容和反馈环节。该文主要验证软件工程场景，本课题需进一步考虑不同部门的独立性及各自的业务处理流程。

3. **Li G, Hammoud H A A K, Itani H, et al. CAMEL: Communicative Agents for "Mind" Exploration of Large Language Model Society. 2023. arXiv:2303.17760.** [论文链接](https://arxiv.org/abs/2303.17760)

   主要内容：研究基于角色扮演和初始提示的智能体协作方式，引导智能体围绕任务展开交流。对本课题的参考价值：用于设计主办方与部门智能体的职责描述和沟通目标，并启发对职责偏离、重复沟通及协作终止条件的关注。

4. **Lewis P, Perez E, Piktus A, et al. Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks. 2020. arXiv:2005.11401.** [论文链接](https://arxiv.org/abs/2005.11401)

   主要内容：提出结合参数化生成模型与非参数化检索记忆的检索增强生成方法，并在知识密集型任务上进行验证。对本课题的参考价值：为各部门智能体检索本部门资料、形成有来源依据的回复提供技术参考，作为跨部门协作的支撑能力。

5. **A2A Project. Agent2Agent Protocol Specification. 在线技术文档，访问日期：2026-10-08。** [官方规范](https://a2a-protocol.org/latest/specification/)

   主要内容：规定独立智能体之间的通信操作与数据模型，包括能力描述、任务管理、消息和成果交换等。对本课题的参考价值：作为主办方与交通等部门独立智能体之间的能力发现、消息传递、沟通任务跟踪和材料交换的实现依据，并据此区分协议通信能力与各部门自行实现的业务处理逻辑。
